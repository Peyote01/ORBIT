# ORBIT
A browser-based cooperative 3D space salvage prototype for 2–4 players. Built with Three.js and an authoritative Node/WebSocket server.

**Status:** first playable source with an experimental multiplayer handheld tractor tool, not a deployed public game. Desktop keyboard and mouse. Generated primitive geometry; no purchased art.

## Run in VS Code
Install Node.js 22+, clone this repository, and check out `prototype/first-playable`. Open the repository folder in VS Code, then use its terminal:
```sh
npm install
npm start
```
Open http://localhost:3000. Start a crew, share the room code, and join from a second browser/device using the **same server URL**. A friend's localhost points to their computer, not yours. For LAN tests use the host computer's LAN IP and port 3000.

```sh
npm run check
npm test
npx playwright install chromium
npx playwright test
```

## Controls and first mission
WASD moves, click the scene to capture the mouse, Shift sprints, T equips or stows the tractor, left-click a loose crate to attach/release it (aim at its visible mesh), mouse wheel adjusts tractor distance, hold R while moving the mouse to rotate cargo, E locks an aligned crate when the cargo grid turns green, and Q/right-click releases the tractor. Hand-pickup and inventory auto-stow are disabled: all salvage uses the handheld tractor. V scans, F fires a sidearm, Space/Ctrl moves vertically during EVA, Esc releases the cursor/closes panels. Captain is marked ★.

1. Walk to BOARD, press E, accept a free contract.
2. Captain uses NAV to travel. Everyone must be aboard with no active tractor attachments.
3. SCANNER: lock grapple; drag the scene to rotate; V scans one of five categories. Compare manufacturer records. Three matches are high confidence; five are certain.
4. Exit the starboard rear airlock (right side near the back), move around the ship and approach the wreck. Aim at a loose crate and left-click to tractor it; E no longer picks up cargo.
5. Guide it toward the starboard rear airlock with the tractor. Follow the physical doorway, position the crate inside the visible cargo bays, rotate until the placement indicator turns green, and press E to secure it. Cargo can only be secured by the tractor's green-grid preview. The placement system automatically tips crates 90 degrees if that is required to fit the bay. Cargo shape, support and overlap rules still matter; volume alone is insufficient.
6. Return all crew aboard. Captain may Crunch: remaining contents are destroyed; the wreck becomes Scrap.
7. Navigate to Market A or B. Compare prices, sell, refuel, repair, and upgrade.
8. At quota deadline, you may still fly to either Market A or B, sell goods, and settle your payment; additional wrecks are blocked until payment or extension. One extension per ship grants seven more days for the same payment. Insufficient funds at settlement repossess the ship and reset cash to 1,000.

## Public hosting
Deploy the **entire Node application** to a host that supports long-running Node processes and WebSockets, with HTTPS and one server instance. Start command: `npm start`; service port: `PORT` (defaults to 3000); health endpoint: `/health`. Dockerfile included.

Static GitHub Pages/Netlify file hosting alone cannot run this multiplayer server. No hosting service has been provisioned by this commit. A public repository is not a playable game URL. Do not submit the repository URL as the competition's live game.

State is in memory: restarting the server resets all rooms. Empty rooms expire after five minutes; disconnected seats are held for 60 seconds. Do not scale to multiple instances without shared room routing/state. Room codes are for casual private sessions, not authentication.

## Scope and limitations
This is an intentionally small first prototype, not the full game. See [design](docs/design.md), [development plan](docs/development-plan.md), and [manual acceptance tests](docs/acceptance.md). Tests do not replace a remote two-person playtest.

## Aft cargo hatch (rear loading)
The back of the ship (positive Z, opposite the bridge) has two retractable bulkhead doors and a loading apron. Press **H** near the aft switch or cargo console to toggle it; **E** at the hatch switch also works. The cargo console includes an Open/Close button. Move bulky cargo through the open rear entrance with the tractor, rotate to fit the available cargo hold, and press E when the grid preview is green. The side EVA airlock remains available for players and smaller crates. Close the rear hatch before flying to the next location. Door closure is blocked if a crate or player occupies the entrance. Cargo that exceeds the starter ship's actual hold dimensions remains oversized and cannot be secured even if it passes through the doorway.

## Cargo handling refinement
The aft door now tests the **entire crate footprint throughout its crossing**, so crates no longer meet an invisible barrier midway through an otherwise open rear hatch. Keep a crate centered in the doorway and ensure its rotated width/height fit the hatch. Once the entire crate has cleared the rear wall, guide it near a clear cargo bay and press **E** when a green preview appears. Placement now uses a short-range magnetic assist to align the crate and settle it onto a supported floor cell (or onto a stable stack); it does not require pixel-perfect alignment or manual lowering to Y=0. The assist cannot pull cargo across the rear wall or through other crates, and the ship's actual hold capacity still applies.

## Tractor-only storage and full-capacity crates
All cargo is acquired by aiming and left-clicking with the handheld tractor. The hand-carry, Q drop and CARGO auto-stow inventory actions have been removed. A crate must be fully aboard and close to an unoccupied supported bay slot before E will secure it. The grid can automatically tip a box upright when required by bay geometry, e.g. a **4×2×4 m (32 m³)** scrap crate in a starter bay sized **2×4×4 m (32 m³)**. Shielding reduces effective bay height and can prevent full-volume placement. While quota payment is due, a captain may return to either market to sell salvage, but cannot travel to new salvage coordinates without paying or using an extension.

## Loose cargo and quota settlement
Any **unsecured, loose crate inside the ship** must be attached with the tractor and secured to a green grid position, or explicitly discarded at the CARGO console, before the captain can depart. Tractor pickup is also allowed when docked at a market to recover crates stranded by older versions; only loose crates already aboard may be attached while docked. Exterior loose cargo does not block departure and remains behind. Cargo consoles list loose crates aboard with a **Discard loose crate** action. Secured cargo remains saleable as before.

**Quota days are capped at the current deadline**, e.g. 7/7 (or 14/14 after the extension). When quota becomes due, return to Market A or B. If the shared credits already cover the payment, the quota is deducted once automatically on docking; otherwise sell secured cargo until the balance is sufficient, at which point it is immediately deducted. Insufficient funds do not cause repossession before the crew has a chance to sell, and the crew may travel between markets while due. Explicit manual settlement while underfunded still forfeits the ship. There is no extra 8/7 day.

## Visual police and raider encounters
During a travel interception, a **procedurally modeled police patrol appears off the ship's port (left) side**, while a **raider attack craft appears off starboard (right)**. Both are positioned outside the translucent side hull, so look out and slightly upward from the bridge. The HUD identifies the attacking ship, side, stage and remaining enemy HP. Police have blue/red warning strobes and a visible scanning cone; raiders have distinctive rust-colored hull panels and orange drives. Hostile cannons flash when the **server actually damages the player's ship**, and the crew cannon beam flashes when a shot is accepted. Destroyed enemy ships emit a brief debris burst; cleared inspections, fines paid, or escaped raiders remove the model. This is a visual upgrade only; current combat controls, damage rates and encounter probabilities are unchanged. Two-player sessions should see the same encounters because all visuals derive from shared server state.

# ORBIT — prototype design
## Goal
A chaotic 15–25 minute cooperative salvage run: the crew argues over clues, cargo space, fuel and deadlines while sharing one vulnerable ship and bank account. No realistic orbital mechanics.

## Established rules
- 2–4 people join a room code, walk around a shared ship and share 1,000 starting credits.
- Contract board offers free and paid salvage rights, including expensive contracts visible from the start. Multiple accepted jobs remain available. Coordinate-only leads and destroyed NPC ships have unauthorized salvage.
- Grapple and rotate derelicts; scan thrusters, doors, paint, landing gear and brand. Compare in-game manufacturer records: at least three matching components support identification, all five give certainty. Models suggest cargo and value, not guaranteed manifests.
- Manipulate all salvage with handheld tractor beams (no hand-carry/auto-stow system), then secure crates on a cubic-meter grid. Check dimensions, overlap, support and height. Largest permitted crate is 4×4×8m (128m³). A 2×2×1 crate occupies 4m³.
- Captain's Crunch destroys all contents left inside and converts the wreck into Scrap, with shutters hiding conversion.
- Two markets change prices with in-game days. Fuel, repairs, weapons, armor, grapple, cargo shielding and bigger ships compete with quota cash.
- Departure after salvage may trigger raiders or police. Police give 20 seconds warning, scan for five seconds, then offer a fine or confrontation. Fighting gives 30 seconds before distress transmission and reinforcements.
- NPC destruction restores a starter ship and removes upgrades, retaining credits less outstanding fine. Quota repossession instead fully restarts at 1,000 credits.
- Quota lasts seven travel days. First station departure in each quota is free. Subsequent station departures and departures from wrecks where salvage was taken count a day. Unfinished wrecks cannot be farmed for free departures after taking cargo.
- Quota is checked on arrival. At a market, players sell before settlement. If the quota becomes due while at a wreck, the crew can still return to Market A or B to sell cargo; new wreck travel is restricted until settlement or extension. Rescue tow remains an emergency option. This arrival/settlement policy is a prototype decision requiring playtest approval.
- One extension per ship adds seven days to the SAME quota. Prototype exposes this when payment is due. Buying a new ship grants its own extension.
- Shielding is per bay and protects only contents stored there. Detection odds are 0.5^level, rolled per bay per inspection. Initial conversion halves volume; further upgrades never shrink it further.

## Prototype tunings, not final design
Initial quota 1,500; later quotas grow 35%, rounded to 50. Starting two holds total 64m³. Ship range costs 10–35 fuel. Free personal wrecks lead into small corporate and bank wrecks. Three model archetypes, eight cargo types, one enemy per hazardous wreck. Crew respawn at medbay and drop carried cargo. Sidearms are supplied; starter ship has no cannon. Shield cap six, ship-size cap two. Installed upgrades transfer on bigger-hull purchase.

## Known approximations to improve
- Exterior geometry currently varies mainly in paint and thrusters. All five clue categories work through scanning and the catalog, but doors, landing gear and branding need distinct visible meshes/decals before claiming the complete visual identification mechanic.
- Rotation is constrained while crew are outside. Wrecks use open decks and simplified collision; avatars can intersect cargo. Tractor cargo-grid packing is authoritative and may auto-tip a crate 90 degrees into a compatible bay; crates are not rigid-body simulations.
- Larger holds expand logically within the same prototype deck; ship art/interior must be resized for full-size crates. Biggest 128m³ crate is a capacity stress case.
- Rival destruction spawns extra illegal crates; it does not yet create a separate fully explorable rival wreck.
- Multi-million contracts are visible as progression placeholders; current cargo prices do not balance their cost. Do not buy these in a normal prototype run.
- No persistence, accounts, voice chat, mobile touch controls or production moderation. Escape/death and rescue-tow economics need balancing.
- Deadline enforcement gates new salvage travel but permits return to either market for selling, and requires an explicit settlement choice. Add a defined automatic payment/failure trigger after market unloading, so crews cannot indefinitely defer settlement.
These limitations are tracked honestly rather than represented as finished features.

## Dependencies and priority
Shared game state → room membership/input authority → ship locomotion → contracts/travel → grapple/scan → salvage/cargo grid → markets/fuel → quota/reset → inspections/combat → upgrades → hosted two-device acceptance.
Build every economic operation on server state. Render snapshots in the browser. Keep prices, rights, deadlines and collisions testable without WebGL.

## Playtest revisions — October 21
- C and the HUD Contracts button open the contract list anywhere, including EVA and transit; purchases still use the shared account and server validation.
- Room code remains visible with Copy code for invitations. Other devices need a reachable host address; localhost is only the local machine.
- Hold Shift to sprint at twice normal speed (also twice carrying speed), with 100 stamina, 25/second drain, and 20/second recovery. Exhaustion requires recovery to 25 before sprinting resumes.
- Identification is never a salvage gate. Crates may be recovered without scans, a model guess, or a grapple. Identification is planning information; model-specific doors/high-value part locations remain future work.
- Grapple remains necessary for rotating/scanning and Crunch. Hold-drag uses cursor capture; V scans during dragging. Rotation packets are limited to 20/second with immediate local preview and server acknowledgment.
- Crunch outputs largest-first Scrap crates from sizes 128, 64, 32, 16, 8, 4, 2, 1 m³. Maximum dimensions are 4×4×8m. No volume is discarded or invented. Prototype wreck yields are 16/40/160m³ by model. Output does not shrink to fit the current ship. Scrap sale value scales with volume.

# Development plan to October 30, 2026
## Architecture
Three.js ES modules render primitive assets. One Node.js process serves static files and a WebSocket room server. Simulation runs at 20Hz, snapshots at 10Hz. Server validates movement bounds, proximity, captain authority, money, cargo geometry and encounter timing. Action IDs suppress repeated purchases within a bounded reconnect session cache. No database in this prototype.

Why this stack: a compact browser build and one deployable service reduce setup dependencies before the deadline. Unity/UE5 remain possible later, but changing engines now would require redoing networking, builds and browser delivery.

## Milestones
- October 20–22: repository, rule tests, connection tests, first 3D client; run from VS Code and repair critical defects.
- October 23–24: complete two remote-player salvage → market → quota run. Fix collision, recovery, crew separation and confusing controls.
- October 25: deploy single-instance HTTPS/WebSocket server; verify external room join and reconnect. Hosting account choice/setup remains required.
- October 26–27: improve five visible identification components, cargo bay geometry, onboarding and quota deadline enforcement. Tune free contracts to sustain early progression.
- October 28: four-person session, weak-connection and reset tests; verify police timers and shielding.
- October 29: freeze new features; fix blockers, verify clean-browser access and submission URL.
- October 30: final remote smoke test and submit before the stated competition deadline. Recheck the program's official timezone and submission requirements.

## Release gates
Two independent physical devices on different networks can create/join the same room. New players complete a run from written in-game instructions. No duplicated money/items. Quota success, extension and repossession are demonstrated. Public URL remains reachable while creator's computer is off. Deploy restart behavior is disclosed.

## Asset workflow
Start with the procedural meshes included here. Use Blender for low-poly modular ship parts and export glTF/GLB for Three.js. Create five legible model signatures, three wreck silhouettes, a consistent crate set and console icons before decorative art. Keep an asset license ledger; only ship assets whose licenses permit redistribution in the game. Do not add unlicensed reference-game models. Asset selection and sourcing have not been performed by this commit.

## Deferred
Detailed ship destruction, persistent economy, large AI populations, procedural wreck interiors, full ship-to-ship maneuvering, voice, mobile input, advanced animation and photorealistic assets.
